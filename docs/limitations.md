# Limitations and evidence discipline

## Four-phase POC boundary

The [reframe CLI](cli-guide.md) implements preparation through a versioned package.
Live AWS/Kiro/Claude Code/Codex acceptance remains pending. Fixture tests verify
control flow, not the correctness/completeness of generated modernization content.
Approval owners are local attestations, not enterprise authenticated signatures.
A reviewer PASS does not establish behavioral equivalence. HTML is an inert review
prototype. Existing assessment provenance requires human confirmation. Cloud setup
may require Transform authentication and administrator connector activation; broad
IAM/Identity Center provisioning is outside this POC. Semantic comparison is bounded,
AI-assisted and requires human review. No application implementation or release runs.


The legacy foundation supplies documentation, phase guides, copyable prompts, role contracts, and manual templates. The prompts have not been validated in an end-to-end pilot and are not installed skills. A local source-validation runner now manages a task manifest, metered operations, artifact sealing, and reviewer preflight. The legacy single-rule Kiro controller implements role dispatch, automatic handoff/rework, assessment import, and an AWS MCP job adapter. Its live integration is not verified; tests use fixtures. That legacy controller provisions no IAM, buckets, connectors, or workspaces; the new CLI adds explicit bucket/workspace/connector operations but no IAM provisioning and provides no .NET implementation or equivalence harness. CLI invocation limits are not hard dollar caps.

The private assessment history is reported context, not reproducible public evidence. Tool-reported completion is not independently verified correctness. Test planning remained a draft in that history, and decomposition did not establish complete domain assignment. No private metrics, inventories, exports, resource identifiers, or execution metadata are republished.

A second model can repeat the first model's mistakes. Independence requires primary-source checks, explicit acceptance criteria, controlled test results, and accountable domain review. No agent may approve itself or claim a human decision.

The diagrams describe intended workflows. The general YAML contracts do not enforce their own requirements. The pilot runner enforces its own narrower record and operation checks, not semantic correctness or human approval. GitHub protections and secret-scanning services are not configured by this documentation. The CardDemo skeleton is not a migration result; its synthetic example is not a source-derived business rule.

The first meaningful implementation milestone is one independently verified rule and one reproducible vertical slice. More generated pages, extracted rules, or passing agent reviews are not substitutes for that evidence.
